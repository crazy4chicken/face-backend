# 小白入门指南：这个项目到底是怎么回事

> 写给完全没接触过的你。不求看完能写代码，只求别人问起"你做了啥"时你能说明白，自己操作时知道在干嘛。

## 一、一句话说清这个项目

你做了一个**人脸识别网站的后台**：手机/网页上传一张人脸照片 → 后台告诉你"这人是谁"。

## 二、名词大白话解释

### 后端（后端服务器）是什么？

一个软件分两半：
- **前端** = 你看得见的部分（网页、APP 界面、按钮）——相当于餐厅的**服务员**
- **后端** = 你看不见的部分（收到照片、算出来是谁、返回结果）——相当于餐厅的**后厨**

你负责的就是后厨。顾客（前端）把菜单（照片）递进来，后厨做菜（识别人脸），再端出去（返回结果）。

### API / 接口是什么？

就是**后厨的窗口**。规定了"你递什么进来、我递什么出去"。

比如你这个项目的几个窗口：

| 窗口 | 你递进去 | 你拿到 |
|---|---|---|
| 注册 | 名字 + 一张单人照 | "注册成功" |
| 识别 | 一张照片 | 这人是谁 / 陌生人 |
| 删除 | 人员编号 | "已删除" |

### GitHub 是什么？

**全球最大的代码托管网站**，可以理解成"程序员专用的百度网盘 + 历史记录器"：

- 代码放上去，换电脑、重装系统都不怕丢
- 每次改动都有记录，改坏了能回到任何一个历史版本
- 多人合作时，各改各的，最后合并，不会互相覆盖

你朋友让你"把代码传到 GitHub"，就是把你的代码备份到他的组织账号（`crazy4chicken`）下面，全组人都能看到。

### git 是什么？

**操作 GitHub 的工具**，装在电脑上。GitHub 是网盘，git 就是上传下载的工具。三个最常听到的词：

- **仓库（repository / repo）** = 一个项目的文件夹在 GitHub 上的家。你的仓库地址是 `github.com/crazy4chicken/face-backend`
- **提交（commit）** = 存档点。就像打游戏存个档，附一句话说明"这次改了啥"
- **推送（push）** = 把本地的存档上传到 GitHub

### 你朋友说的"提交规范"和"签名"是什么？

- **Conventional Commits（提交规范）** = 存档留言的格式要求，必须以类型开头，比如 `feat:`（新功能）、`fix:`（修 bug）。就像快递单必须按格式填，方便别人一眼看懂你改了什么
- **提交签名（Verified）** = 给存档盖个**防伪章**。没盖章的存档谁都能伪造署名（写别人的名字）；盖了章 GitHub 就显示绿色 "Verified"，证明"这确实是 Luckycyh 本人提交的"。你朋友要的就是这个绿标

### 端口（port）是什么？

一台电脑能同时跑很多网络服务，**端口就是门牌号**。你的后端住在这台电脑的 18000 号门。前端要找你，就得敲 `电脑地址:18000`。

学校服务器说"10000 以下不能用"，意思是 1~9999 号门都被学校占了或封了，所以我们选了 18000 号。

### JWT / 登录鉴权是什么？

**门禁卡系统**。没它之前，任何人都能调用你的后端（乱注册、乱删人）。有了它：

1. 先用账号密码登录 → 领一张**门禁卡**（JWT，就是一长串字符）
2. 之后每次调用都要**刷卡**（请求里带上这串字符）
3. 卡是假的 / 过期的（默认 2 小时）→ 拒绝服务，返回 401

### 数据库（PostgreSQL）是什么？

**存人员信息的柜子**。你注册过的人（名字、学号、人脸特征）都存在里面，后端重启了数据也不丢。PostgreSQL 是其中一个品牌（免费、主流、学校项目够用）。

### 人脸"特征"是什么？

后台**不存照片本体**，而是把人脸算成一串 512 个数字（叫"特征向量"），可以粗略理解成"人脸的指纹"。识别就是：把新照片也算成指纹，跟柜子里的指纹比对，像到一定程度（相似度 ≥ 0.45）就认为是同一个人。

好处：就算数据库泄露，别人拿到的也只是数字串，不是你的照片。

### 模型（buffalo_l）是什么？

**AI 的大脑文件**（282MB）。不是代码，是别人训练好的"认脸经验"。它放在你电脑的固定位置（`C:\Users\lucky\.insightface\models\`），**换电脑要一起搬**。

## 三、这个项目从头到尾做了什么

按时间顺序：

1. **选型**：看了 GitHub 上最火的人脸识别库，选了 InsightFace（最火那个 face_recognition 太老、Windows 装不上）
2. **写后端**：三个核心文件——收照片的、算人脸的、存数据的
3. **测试**：用明星合影照片自动测试了 21 次，全过（认得出本人、认不出陌生人、坏图片会报错……）
4. **修漏洞**：堵了像素炸弹（恶意图片撑爆内存）、加了登录门禁卡等
5. **换数据库**：按你的要求从简易版（SQLite）换成正式版（PostgreSQL）
6. **改端口**：8000 → 18000（学校要求）
7. **上传 GitHub**：装工具、登录你的账号（Luckycyh）、建仓库、推送
8. **按朋友要求整改**：提交留言改成规范格式、署名改成你、加了 Verified 防伪章

## 四、日常怎么用这个后端

### 启动（在 VS Code 里）

按 **F5**，或者终端里运行：

```bash
cd 项目文件夹
uvicorn app.main:app --host 0.0.0.0 --port 18000
```

启动后浏览器打开 `http://127.0.0.1:18000/docs` 能看到一个**在线测试页面**，可以直接传照片试效果，不用写任何代码。

### 测试有没有坏

```bash
python smoke_test.py
```

看到 `全部通过` 就是好的。

### 改了代码怎么传到 GitHub

```bash
git add -A                              # 把改动打包
git commit -m "feat: 这次改了啥"         # 存档（记得用规范格式）
git push                                # 上传
```

### 部署到学校服务器时要带什么

1. 代码（`git clone` 拉下来就有）
2. 模型文件夹 `buffalo_l`（从你电脑 `.insightface/models/` 拷过去）
3. 服务器上装好 PostgreSQL
4. 改掉两个"出厂密码"：JWT 密钥和登录密码（不然谁都能进）

## 五、常见疑问

**Q：代码在 Temp（临时文件夹）里安全吗？**
A：不安全，系统清理会删。尽早把 `face_backend` 文件夹挪到比如 `D:\Projects\` 下面。不过反正 GitHub 上有完整备份，真删了也能拉回来。

**Q：朋友还能看到我的代码吗？**
A：能，仓库在他组织下，他是管理员。但他看不到你电脑上的东西，只能看到你 push 上去的。

**Q：我 push 错了怎么办？**
A：历史都在，能回退。到时候叫我。

**Q：这个"AI"会联网把我的照片传出去吗？**
A：不会。识别计算全在你自己电脑上完成，模型文件是本地的，不联网。
